# phpList 3.6.17 Two-Site Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the shared NFS phpList fork from 3.6.16 to the official 3.6.17 tag, preserve every NFS customization, and deploy independently verified artefacts to SegurosMais and SimulacaoCreditoPessoal/Saldo.

**Architecture:** Integrate the official tag into an isolated upgrade branch, retain the common customized core, and overlay exactly one site-specific `NFSCustomizationsPlugin` when building each artefact. Production promotion is sequential, preserves remote configuration and runtime data, and has file plus database rollback evidence before upload.

**Tech Stack:** PHP 7.2/8.3, phpList 3, Git, Bash, Docker, FTPS, MySQL/MariaDB.

**Spec:** `docs/NFSCustomizationsPlugin.md`

## Global Constraints

- Production target is the official stable tag `v3.6.17`; do not deploy a 3.7 release candidate.
- Preserve all NF01-NF11 behavior and the fixed opt-in destination of each overlay.
- Never deploy both overlays to one installation.
- Never overwrite remote `config/config.php`, `config/config_extended.php`, uploads, attachments, temporary data, or unknown external plugins.
- Obtain and verify a restorable code backup and database backup for each site before promotion.
- Validate PHP 8.3 for SegurosMais and PHP 7.2 for SimulacaoCreditoPessoal.
- Deploy one site, validate it, and only then deploy the second.
